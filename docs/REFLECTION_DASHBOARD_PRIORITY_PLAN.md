# Reflection Dashboard — приоритетный план (март 2026)

Этот документ фиксирует **первый приоритет** и рабочий порядок на ближайшие 4 недели для трёх направлений:

1. Reflection Dashboard
2. Web4 Mesh
3. HCP Marketplace

## Что берём в первую очередь

**Берём первым Reflection Dashboard.**

Почему:
- даёт самый быстрый пользовательский эффект (видимость памяти/рефлексий и ручное управление качеством);
- снижает риски для следующих этапов (Mesh и Marketplace проще строить, когда уже есть стабильный слой наблюдаемости и модерации рефлексий);
- позволяет собирать метрики, которые потом пригодятся для p2p-синхронизации и экономики marketplace.

## Приоритеты на 4 недели

### Неделя 1–2: Reflection Dashboard до daily-use

Цель: довести дашборд до режима «используется каждый день».

- Инвентаризация текущего UI и очистка legacy-компонентов.
- Формализация API-контракта backend → frontend:
  - граф памяти;
  - последние N рефлексий;
  - confidence/contradiction метрики;
  - heatmap-данные.
- Реал-тайм обновление (WebSocket или polling 3–5 сек).
- Базовые интерактивные действия:
  - Approve → canonical;
  - Reject → contradiction + trigger rethink;
  - Edit → новая версия узла.

**Definition of Done (W2):**
- оператор может просматривать поток рефлексий в реальном времени;
- оператор может approve/reject/edit без ручных обходов через CLI;
- есть минимальные метрики доверия и противоречий.

### Неделя 3: Web4 Mesh v0

Цель: перейти от RFC к первой живой ноде.

- Выбрать стек (по умолчанию: `js-libp2p`).
- Зафиксировать 3 базовых сообщения:
  - `Announce`;
  - `SyncGraph`;
  - `PushReflection`.
- Поднять CLI-ноду v0 с обнаружением пиров и минимальной синхронизацией графа.

**Definition of Done (W3):**
- одна нода запускается локально;
- есть обмен минимум одним типом сообщения между двумя peer-процессами.

### Неделя 4: HCP Marketplace MVP (внутренний)

Цель: закрытый MVP без блокчейна.

- Сущность `Item` и CRUD API.
- Простой список товаров + действие «Купить/Установить».
- Внутренние кредиты вместо on-chain платежей.
- Интеграция с runtime через PluginManager (загрузка купленного item).

**Definition of Done (W4):**
- есть 5–10 тестовых items;
- item можно «купить» и добавить в runtime в пределах одной инстанции LS.

## Риски и сдерживающие меры

- **Риск:** распыление команды между 3 направлениями.
  - **Мера:** жёсткий WIP-лимит: сначала закрываем DoD по Reflection Dashboard.
- **Риск:** нестабильный API между backend/frontend.
  - **Мера:** версионированный контракт и smoke-тесты на ключевые эндпоинты.
- **Риск:** ранний уход в блокчейн-платежи для Marketplace.
  - **Мера:** фиксируем «внутренние кредиты» как единственный платёжный режим для MVP.

## Рекомендованная последовательность внедрения

1. Reflection Dashboard (обязательный first milestone).
2. Web4 Mesh v0 (минимальная сеть и протокол).
3. HCP Marketplace MVP (закрытый контур, без on-chain).

Итог: такой порядок даёт максимальную скорость обратной связи и минимизирует архитектурные откаты.
