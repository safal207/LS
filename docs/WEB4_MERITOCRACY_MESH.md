# Web4 Meritocracy Mesh
**Децентрализованная сеть локальных LS-узлов с меритократическим распределением задач и синергией**

**Версия:** 0.2 (обновление от 18 февраля 2026)  
**Автор:** Главный архитектор LS  
**Статус:** Draft → Phase 22 (после Rust Parity)

## 1. Vision

Если каждый локальный LS эффективнее топовых облачных моделей в агентных сценариях (а мы уже на пути к этому), то **миллионы независимых узлов** могут объединиться в единую сеть, которая:

- превосходит любой дата-центр по эффективности;
- работает полностью децентрализованно;
- вознаграждает лучших по заслугам (Meritocracy);
- создаёт синергию, недоступную централизованным системам.

**Цель:** превратить LS из «локального агента» в **глобальную когнитивную инфраструктуру Web4** — основу новой цифровой экономики 2027–2030.

## 2. Ключевые принципы

1. **Meritocracy** — не размер железа, а реальные результаты решают, кто получает задачу.
2. **Синергия** — узлы делятся лучшими адаптерами, данными и знаниями автоматически.
3. **Децентрализация** — нет единого сервера, нет единой точки отказа.
4. **Value Alignment** — сеть защищена от «тёмной стороны» через HCP и встроенные guardrails.
5. **Экономика** — узлы зарабатывают Merit Points → реальные токены/привилегии.

## 3. Архитектура (высокоуровневая схема)

```mermaid
graph TD
    A[Локальный LS-узел] --> B[Merit Score Engine]
    B --> C[Global Merit Ledger (Web4 Gossip)]
    A --> D[Web4 Mesh Router]
    D --> E[Task Execution Plan Generator]
    E --> F[CIP / LIP / HCP]
    G[Производители моделей/железа] --> H[Investment & Adoption Layer]
    H --> A
```

**Основные компоненты:**

- **Merit Score Engine** (внутри каждого узла);
- **Global Merit Ledger** (распределённый, gossip-based);
- **Merit-based Task Router**;
- **Synergy Protocol** (автоматический обмен LoRA, beliefs, synthetic data);
- **Incentive Layer** (Merit Points → экономика).

## 4. Merit Score — как считается «заслуга»

### 4.1 Формула v0.1 (текущая базовая)

```python
MeritScore = (
    0.35 * QualityScore          # точность и полезность результата
  + 0.25 * SpeedScore            # реальное время выполнения задачи
  + 0.20 * ReliabilityScore      # uptime + success rate
  + 0.15 * ContributionScore     # сколько полезного отдал в сеть
  + 0.05 * AlignmentScore        # соблюдение Value Guardrails
) * TrustMultiplier
```

- Обновляется после каждой выполненной задачи через CIP.
- Хранится локально + gossip в сеть (каждые 60 сек).
- За фейковые заслуги — штраф и временный бан.

### 4.2 Формула v0.2 (предлагаемая после полевых тестов)

```python
MeritScore_v0_2 = (
    0.40 * QualityScore
  + 0.20 * SpeedScore
  + 0.20 * ReliabilityScore
  + 0.10 * ContributionScore
  + 0.10 * AlignmentScore
) * TrustMultiplier
```

**Почему такой сдвиг весов:**
- увеличен вес `QualityScore` (0.35 → 0.40), чтобы сеть оптимизировалась на качество конечного результата, а не на «быстрые, но слабые» ответы;
- повышен вес `AlignmentScore` (0.05 → 0.10), чтобы укрепить безопасность и соответствие HCP/Value Guardrails на масштабе;
- снижена доля `ContributionScore` (0.15 → 0.10), чтобы исключить инфляцию заслуг через «количественный шум»;
- `SpeedScore` и `ReliabilityScore` оставлены критичными, но без доминирования над качеством.

### 4.3 Примеры расчёта Merit Score v0.2

Предполагаем шкалу 0..1 и `TrustMultiplier = 1.0`.

| Узел | Quality | Speed | Reliability | Contribution | Alignment | Итоговый MeritScore v0.2 |
|------|---------|-------|-------------|--------------|-----------|--------------------------|
| Node-A (research) | 0.90 | 0.70 | 0.95 | 0.80 | 0.95 | 0.87 |
| Node-B (fast generalist) | 0.78 | 0.95 | 0.88 | 0.72 | 0.82 | 0.82 |
| Node-C (unstable) | 0.84 | 0.80 | 0.62 | 0.75 | 0.90 | 0.79 |

Расчёт для Node-A:  
`0.40*0.90 + 0.20*0.70 + 0.20*0.95 + 0.10*0.80 + 0.10*0.95 = 0.865 ≈ 0.87`

## 5. Как работает сеть на практике

1. Пользователь даёт задачу своему LS.
2. Локальный узел оценивает сложность и публикует в Web4 Mesh.
3. Router выбирает 3–7 узлов с наивысшим Merit в данной доменной области.
4. Задача дробится (WEB4MESHEXECUTIONPLANGENERATOR).
5. Узлы выполняют → возвращают результат + обновляют Merit.
6. Синергия: лучшие адаптеры автоматически распространяются по сети.

## 6. Экономическая модель (почему производители будут инвестировать)

- **Merit Points** можно конвертировать в:
  - приоритетный доступ к новым моделям;
  - скидки на железо;
  - реальные токены (в будущем on-chain).

Производители (NVIDIA, Groq, Cerebras, Huawei, Apple и т.д.) получат:
- готовый рынок сбыта своих чипов/моделей;
- стандарт Web4 (наши протоколы);
- данные о реальном использовании (анонимизированные).

### 6.1 Что получает производитель (value matrix)

| Категория выгоды | Что получает производитель | Ориентир v0.2 |
|------------------|----------------------------|---------------|
| Hardware demand | Прямой канал к узлам, которым нужен апгрейд железа | Ускорение продаж через профильные доменные кластеры |
| Коммерческие стимулы | Программируемые скидки и офферы для Merit-узлов | 15–25% скидки на железо для top-tier узлов |
| Model distribution | Приоритетный rollout оптимизированных локальных моделей/LoRA | Early access для узлов с высоким Reliability/Alignment |
| Adoption analytics | Анонимизированная аналитика реального потребления | Еженедельные телеметрические срезы по доменам |
| Ecosystem lock-in | Интеграция в стандарт Web4 протоколов | Рост LTV за счёт повторных апгрейдов/подписок |

**Прогноз:** уже в 2027 году 30–40 % новых локальных инстансов будут запускаться именно под Web4 Mesh.

## 8. Риски и mitigation

- **Захват сети** → Merit + HCP + on-chain governance (2028).
- **Коллапс качества** → автоматический Quality Guardrail.
- **Bootstrapping** → первые 5000 узлов — через GhostGPT и наш коммьюнити.

## 9. Почему это сильнее Bittensor (позиционирование)

Web4 Meritocracy Mesh не ограничивается оценкой «модель против модели». В нашей архитектуре меритократия применяется ко **всему жизненному циклу задачи**: декомпозиция, маршрутизация, выполнение, валидация, обмен артефактами и обновление репутации.

Ключевое отличие — встроенный **HCP + Value Alignment слой**, который влияет на Merit Score и ограничивает токсичное поведение сети. Это даёт не только конкуренцию за точность, но и управляемость качества/безопасности на уровне инфраструктуры.
