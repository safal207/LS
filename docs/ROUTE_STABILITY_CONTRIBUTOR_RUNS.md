# Route Stability Contributor Runs

Status: **contributor protocol for independent route-stability runs**.

This document explains how contributors can help test the LS Nash-style
route-stability proxy across different models, runtimes, operating systems, and
hardware.

## Goal

Collect independent, reviewable runs that answer a narrow question:

```text
Does the same cooperative route-stability evidence chain behave consistently
across different contributor environments, fixtures, model outputs, and hardware?
```

This is not a model leaderboard. It is a contributor-run protocol for testing
route evidence, reproducibility, fixture coverage, and environment sensitivity.

## Boundary

```text
Nash-style route stability proxy, not a formal proof of Nash equilibrium.
```

Contributor runs must not claim:

```text
formal Nash equilibrium;
global model ranking;
global contributor ranking;
global hardware ranking;
statistical sufficiency;
production-grade governance;
that one route generalizes to all PR reviews.
```

## What Contributors Can Test

| Track | What to run | Reviewer value |
| --- | --- | --- |
| Reproducibility | Run the current deterministic route-stability probe locally. | Checks whether the canonical sample and test path work outside the maintainer environment. |
| Hardware matrix | Run the same probe on different OS / CPU / GPU / RAM setups. | Finds environment assumptions and platform drift. |
| Model-output matrix | Submit role-output fixtures generated by different local or hosted models. | Tests whether the route-stability path can compare different cooperative role outputs. |
| Negative fixtures | Add intentionally invalid fixtures. | Hardens schema rejection and prevents weak evidence from entering reviewer discussion. |

## Minimum Local Check

From the LS repository root:

```bash
python -m pip install jsonschema pytest
PYTHONPATH=.:python:python/modules python -m pytest python/tests/test_nash_route_stability.py
python scripts/run_nash_route_stability_demo.py --json
```

Expected result:

```text
pytest passes;
run_nash_route_stability_demo.py --json emits a valid route-stability payload;
interpretation_boundary remains explicit.
```

## Contributor Environment Metadata

Each contributor run should report the environment in a short Markdown note or
JSON manifest.

Recommended fields:

```text
runner_id: pseudonym or GitHub handle
run_date_utc: YYYY-MM-DD
os: Linux / macOS / Windows / WSL
python_version: e.g. 3.11.8
cpu: model name or family
ram_gb: approximate RAM
accelerator: none / CUDA GPU / Apple Silicon / other
accelerator_memory_gb: optional
model_provider: local / hosted / sample / human
model_name: e.g. qwen2.5:7b, llama3.1:8b, claude, gpt, human-reviewer
model_runtime: ollama / vllm / llama.cpp / API / manual
quantization: optional, e.g. q4_K_M
fixture_id: sample or custom fixture path
route_key: e.g. pr_review>local>gonka>mimo
command: exact command used
result_file: output file path
notes: short limitations or anomalies
```

Do not include:

```text
API keys;
private prompts;
private repository diffs;
personal data;
proprietary customer data;
secrets or tokens.
```

## Suggested Output Paths

For local uncommitted runs:

```text
reports/trails/contributor/<runner_id>/<run_id>/nash_route_stability.json
reports/trails/contributor/<runner_id>/<run_id>/environment.md
```

For curated checked-in examples after review:

```text
examples/route-stability/contributor-runs/<run_id>.json
examples/route-stability/contributor-runs/<run_id>.md
```

Runtime reports should stay uncommitted until promoted into curated examples.

## Model-Output Fixture Path

For model-specific tests, contributors should provide role outputs rather than
private model traces.

Preferred shape:

```text
docs/examples/pr_role_outputs.<runner_or_model_slug>.json
```

The fixture should describe role outputs used by the route-stability or PR-review
benchmark path, without exposing secrets or private data.

A future runner may accept:

```bash
python scripts/run_nash_route_stability_demo.py \
  --role-outputs docs/examples/pr_role_outputs.<runner_or_model_slug>.json \
  --json
```

Until that flag exists, contributor submissions should clearly separate:

```text
current deterministic probe results;
proposed model-output fixture;
manual interpretation notes.
```

## Contributor PR Checklist

A contributor PR should include:

```text
1. What track is this? reproducibility / hardware matrix / model-output matrix / negative fixture.
2. What environment was used?
3. What command was run?
4. What fixture was used?
5. What result was produced?
6. Does the result preserve the interpretation boundary?
7. Does the PR avoid secrets and private data?
8. Is this a curated example or just a proposed fixture?
```

## Acceptance Criteria

A contributor run can be accepted as reviewer evidence only if:

```text
schema validation passes or fails intentionally;
negative fixtures are explicitly expected to fail;
metadata is enough to reproduce or interpret the run;
non-claims are preserved;
no secrets or private data are included;
claim remains route-stability proxy, not formal Nash proof.
```

## First Useful Contributor Tasks

| Task | Good first PR shape |
| --- | --- |
| Reproduce current probe on Linux CPU-only | Add a short `environment.md` note and output summary. |
| Reproduce current probe on Windows / WSL | Add OS-specific notes if anything differs. |
| Reproduce current probe on Apple Silicon | Add runtime notes and output summary. |
| Add unsupported-decision negative fixture | Add fixture + schema rejection test. |
| Add not-stable-yet fixture | Add curated sample where `stability.decision == not_stable_yet`. |
| Add role outputs from a local model | Add sanitized `pr_role_outputs.<slug>.json` fixture and interpretation note. |

## Reviewer Interpretation

A strong contributor matrix would let reviewers say:

```text
The route-stability evidence path has been exercised by multiple contributors
across different environments and fixtures, while preserving the same schema,
test, artifact, and non-claim boundaries.
```

That is the right claim.

The wrong claim would be:

```text
This proves a formal Nash equilibrium or ranks all models globally.
```
