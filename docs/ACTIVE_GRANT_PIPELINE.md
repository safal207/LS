# Active Grant Pipeline

## Purpose

This document is a safe, public-facing grant pipeline for LS and adjacent research directions.

It tracks which funding paths are active, what each path should be used for, what not to mix, and the next practical action.

This file intentionally avoids private data:

- no personal phone numbers;
- no private email excerpts;
- no submission IDs;
- no confidential reviewer comments;
- no non-public portal details.

## Core rule

Do not merge all project narratives into one application.

Use separate tracks:

```text
LS / Personal Cognitive Garden
-> AI-assisted human development governance
-> human-owned cognitive graphs
-> anti-surveillance safety boundary

CML / LTP / trace systems
-> causal memory
-> deterministic replay
-> trace-based oversight
-> AI safety evaluation

PythiaLabs / ProofPath
-> evidence gates
-> pre-execution checks
-> high-risk AI-agent/API actions
-> security / RegTech / responsible AI infrastructure

Cyprus / startup path
-> commercialization
-> business plan
-> market need
-> differentiation
-> company formation after approval, if applicable
```

## Track 1 — Schmidt / large trustworthy AI grants

### Best framing

```text
Trace-based oversight and causal memory for trustworthy AI systems.
```

Personal Cognitive Garden can be used as an additional governance example, but the main frame should remain:

```text
agent traces
-> deterministic replay
-> causal memory
-> evaluation harness
-> scalable oversight
```

### Use these artifacts

- `GRANT.md`
- `docs/GRANT_READY_BRIEF_PERSONAL_COGNITIVE_GARDEN.md`
- `docs/PERSONAL_COGNITIVE_GARDEN_RED_TEAM.md`
- `docs/PERSONAL_COGNITIVE_GARDEN_RUNNER.md`
- `schemas/personal-cognitive-garden-update.v0.1.json`

### Recommended action

Check whether the active portal allows updates before the deadline. If yes, add concise links to the new LS grant reviewer path and safety boundary. If not, leave the submitted application untouched.

### One-sentence update

```text
Since submission, I added a public grant reviewer path, runnable demo, machine-readable schema, and red-team safety boundary for human-owned AI-assisted development governance.
```

```text
The prototype now includes a stronger public artifact path with runnable demos, evidence-gate examples, and clearer reviewer documentation.
```

## Track 3 — LTFF / EA Funds

### Best framing

```text
AI safety infrastructure for causal memory, traceability, and governance of AI-assisted systems.
```

### Use these ideas

- AI systems increasingly infer and store human goals, skills, weaknesses, and decision traces;
- ungoverned memory can become opaque profiling;
- causal memory and reviewable update systems can reduce misuse;
- local-first, human-owned state is a safer default;
- red-team scenarios can test whether private data export is blocked.

### Recommended action

Do not submit a new similar application. Send at most one short update to the existing application when there is a meaningful artifact improvement.

### Update candidate

```text
Since the original submission, I consolidated a public LS grant reviewer path, added a runnable Personal Cognitive Garden demo, introduced a red-team employer-surveillance scenario, and documented an anti-surveillance safety invariant for human-owned cognitive graphs.
```

## Track 5 — OpenAI Cybersecurity Grant

### Best framing

```text
Defensive pre-execution evidence gates for AI-agent security actions.
```

This is not the right place for Personal Cognitive Garden unless reframed as privacy/security governance, and even then ProofPath is cleaner.

### Use these ideas

- agent action authorization;
- evidence freshness;
- human approval for irreversible actions;
- audit logs;
- CI/security integration;
- dangerous action blocking;
- defensive tooling.

### Recommended action

Wait. Update only if ProofPath / PythiaLabs adds a stronger security-specific demo.

## Track 6 — Cyprus Startup Visa / RIF / NCC

### Best framing

```text
AI assurance / RegTech / responsible AI infrastructure startup.
```

This is a commercialization path, not a grant-research path.

### What they need

- innovation;
- technological differentiation;
- justified market need;
- commercialization path;
- financial scenarios;
- risks and mitigations;
- evidence of MVP progress;
- why the solution is not easily replicated.

### Recommended action

Prepare a business plan package:

```text
Annex I
+ business plan
+ worst/base/best case financial model
+ market need
+ competitor differentiation
+ product roadmap
+ risk mitigation
+ evidence package
```
