# Idea Flood vs Execution Bottleneck

## Контекст
AI Venture Engine быстро генерирует и валидирует гипотезы. На практике первый масштабный сбой появляется не в качестве идей, а в дисбалансе между входящим потоком проектов и пропускной способностью исполнения.

Это ловушка **Idea Flood vs Execution Bottleneck**:

- идей и подтверждённых возможностей становится слишком много;
- ресурсов на реализацию (агенты, бюджет, внимание, инфраструктура) — ограниченно;
- система начинает деградировать по качеству портфеля.

## Симптомы архитектурной ловушки

1. **Перегрев бэклога**: количество `validated_ideas` растёт быстрее, чем `active_projects` закрывают ключевые milestones.
2. **Фрагментация капитала**: слишком тонкое распределение treasury по многим проектам → ни один не получает критическую массу ресурсов.
3. **Переключения контекста у агентной сети**: рост очереди коротких задач и снижение глубины выполнения.
4. **Метрики «суеты» вместо прогресса**: высокий throughput задач при низком росте revenue/retention.
5. **Залипание в pre-seed экспериментировании**: много запусков, мало scale-up.

## Почему ломается даже «умная» система

Даже при сильном Idea Engine ограничение остаётся на стороне:

- execution capacity (время и качество агентного исполнения),
- governance bandwidth (сколько решений реально можно принять качественно),
- capital concentration (сколько проектов можно полноценно профинансировать одновременно).

Если эти ограничения не моделируются явно, система оптимизирует не ценность, а скорость генерации новых гипотез.

## Что добавить в AI Venture Engine

Нужен отдельный слой: **Portfolio Flow Controller** между Validation Engine и Project Factory.

```text
Idea Engine
  ↓
Validation Engine
  ↓
Portfolio Flow Controller   ← новый управляющий контур
  ↓
Project Factory
  ↓
Execution Network
  ↓
Capital Allocator
```

## Механика Portfolio Flow Controller

### 1) WIP-лимиты на уровне портфеля
Не запускать новые проекты, если достигнут лимит одновременно исполняемых стартапов.

Пример:
- `max_active_projects = 12`
- `max_incubation_projects = 5`
- `max_scale_projects = 3`

### 2) Stage-gate с жёсткими порогами
Каждый проект проходит ворота с обязательными метриками:

- Gate A (problem-solution fit): `signup_rate`, `CAC_proxy`, `time_to_MVP`
- Gate B (early PMF): `retention_d7/d30`, `activation_rate`
- Gate C (scale): `LTV/CAC`, `payback_period`, `gross_margin`

Не прошёл порог — проект freeze/kill, ресурсы возвращаются в treasury.

### 3) Dynamic capital concentration
Капитал распределяется не равномерно, а по кривой убеждённости:

- top 20% проектов получают 60–80% execution budget;
- bottom сегмент финансируется минимально до подтверждения тяги.

### 4) Admission control по expected value
Перед созданием `project_object` считать:

`expected_value = p(success) * upside - required_capital - execution_risk_penalty`

Запускать только идеи выше динамического cut-off, зависящего от текущей загрузки системы.

### 5) Anti-thrashing правила для агентной сети
- минимальная длительность фокуса на проекте;
- ограничение на частоту реприоритизации;
- reserved capacity для «почти взлетевших» проектов.

## Набор обязательных метрик контроля

Минимальный дашборд Portfolio Flow Controller:

- **Idea-to-Execution Ratio** = validated ideas / started projects
- **Execution Saturation** = active tasks / effective agent capacity
- **Capital Concentration Index** (доля бюджета в top-N)
- **Kill Latency** (время от плохих сигналов до остановки)
- **Scale Conversion Rate** (доля проектов, дошедших до stage scale)

## Практическое правило

Для большинства AI-native venture систем работает простая эвристика:

- лучше 10 проектов с глубоким исполнением,
- чем 100 проектов с поверхностной активностью.

Система выигрывает не там, где больше идей, а там, где лучше дисциплина отбора, остановки и концентрации ресурсов.

## Коротко

**Главная проблема AI Venture Engine — не дефицит идей, а дефицит качественного исполнения под ограниченный капитал и внимание.**

Решение: ввести Portfolio Flow Controller как обязательный контур управления потоком проектов, иначе рост числа гипотез почти гарантированно приводит к деградации портфельной доходности.
